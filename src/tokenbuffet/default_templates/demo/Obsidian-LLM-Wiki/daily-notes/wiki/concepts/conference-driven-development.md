# Conference-driven development

## Definition

Conference-driven development is the practice of building or releasing software in order to prepare for a conference talk. The deadline of a talk becomes the driver for concrete engineering work. Simon Willison uses the phrase to describe how his [[DjangoCon US 2024]] talk led him to write and release [[DJP]], a [[Plugin system]] for Django, in September 2024.

## Key Characteristics

- The conference talk sets a fixed deadline that pushes the work to completion.
- The talk topic determines the software that gets built, such as a plugin system for the talk about plugin systems.
- The software is a real release, not only a demo prepared for the stage.
- The pattern is described playfully, but the engineering output is concrete.
- Speaking commitments shape the open source roadmap of the project.

## Applications

- A maintainer proposes a talk on a feature they have not yet built, then ships that feature before the event.
- A speaker turns a demo into a published package so the audience can install and try it after the talk.
- Open source projects use upcoming conference slots to set release dates and priorities for the month.
