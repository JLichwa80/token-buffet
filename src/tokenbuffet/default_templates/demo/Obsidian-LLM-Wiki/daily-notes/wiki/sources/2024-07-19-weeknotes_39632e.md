## Core Content

Simon Willison's weeknotes for 19 July 2024 cover three threads. The first is the release of [[entities/gpt-4o-mini|GPT-4o mini]], which he calls the cheapest high-performing hosted model, noting its **16,000 token output limit** ([[concepts/16000-token-output-limit|16000 token output limit]]). He shipped [[entities/llm|LLM]] 0.15 to support the model, and it became LLM's default, replacing GPT-3.5 Turbo. The second is [[entities/sqlite-utils|sqlite-utils]] 3.37, released to fix a numpy-related crash that surfaced in LLM when installed via Homebrew; it also added compound primary key support and testing against Python 3.13. The third and largest thread is a [[concepts/staging-environment|staging environment]] for [[entities/datasette-cloud|Datasette Cloud]]. The service has comprehensive tests and [[concepts/continuous-deployment|continuous deployment]], but no separate environment in which to exercise its code for deploying to [[entities/fly-machines|Fly Machines]] without touching production. Much of the work has involved removing hard-coded values from the codebase and [[entities/github-actions|GitHub Actions]] workflows, a refactoring Willison credits in part to [[entities/claude-3-5-sonnet|Claude 3.5 Sonnet]].

## Main Points

- **GPT-4o mini** was released on 19 July 2024 as the cheapest high-performing hosted model, with a 16,000 token output limit.
- **LLM 0.15** added GPT-4o mini support and made it the default model, replacing GPT-3.5 Turbo.
- **A numpy crash** that appeared only when LLM was installed via Homebrew was fixed in the sqlite-utils dependency, shipped as **sqlite-utils 3.37**.
- **Datasette Cloud** has comprehensive tests and continuous deployment but no staging environment for testing its Fly Machines deployment code separately from production.
- **Building the staging environment** exposed many hard-coded values in the codebase and GitHub Actions workflows; Willison used Claude 3.5 Sonnet to help refactor the workflow YAML.
