## Core Content

This weeknotes post by Simon Willison, covering the week ending 21 January 2024, centres on the [[entities/datasette|Datasette]] plugin ecosystem. Willison finished [[entities/datasette-edit-templates|datasette-edit-templates]] 0.4.3, which lets templates be edited inside Datasette and served per instance or per domain for [[entities/datasette-cloud|Datasette Cloud]]. Work on [[concepts/plugin-compatibility|plugin compatibility]] for Datasette 1.0 began after [[entities/datasette-cluster-map|datasette-cluster-map]] broke on Datasette Cloud. Its 0.18 release fixed the problem and added [[entities/playwright|Playwright]] browser tests, following a pattern from [[entities/datasette-comments|datasette-comments]]. Willison also released [[entities/datasette-test|datasette-test]] 0.2 for cross-version plugin testing and started [[entities/datasette-build|datasette-build]], an early tool for loading static data files into [[entities/sqlite|SQLite]]. The post closes with two days at the in-person [[entities/python-software-foundation|Python Software Foundation]] board meeting, spent on strategy.

## Key Entities

- [[entities/datasette|Datasette]]: the core open-source data exploration tool that the whole post builds on.
- [[entities/datasette-cloud|Datasette Cloud]]: the hosted deployment used as a real-world testbed.
- [[entities/datasette-test|datasette-test]]: new testing utilities that work across Datasette versions.
- [[entities/datasette-build|datasette-build]]: early-stage tool for converting static data files to SQLite.
- [[entities/datasette-cluster-map|datasette-cluster-map]]: plugin that broke on Datasette Cloud and was fixed in 0.18.
- [[entities/datasette-edit-templates|datasette-edit-templates]]: plugin for editing Datasette templates in place.
- [[entities/datasette-search-all|datasette-search-all]]: plugin that reuses the Playwright testing pattern.
- [[entities/datasette-comments|datasette-comments]]: Alex Garcia's plugin whose tests established the Playwright pattern.
- [[entities/playwright|Playwright]]: browser automation library used for plugin UI tests.
- [[entities/sqlite|SQLite]]: the destination database format for datasette-build.
- [[entities/python-software-foundation|Python Software Foundation]]: the organisation whose board meeting the author attended.

## Key Concepts

- [[concepts/plugin-compatibility|plugin compatibility]]: keeping plugins working across Datasette versions as 1.0 approaches.
- [[concepts/plugin-configuration|plugin configuration]]: the mechanism that is changing between Datasette versions.
- [[concepts/browser-automation-testing|browser automation testing]]: driving a real browser to test plugin JavaScript.
- [[concepts/version-controlled-data-files|version-controlled data files]]: small datasets kept in Git and loaded into SQLite.

## Main Points

- **Datasette 1.0 is approaching**, which prompted work on **plugin compatibility**. A JSON API change broke [[entities/datasette-cluster-map|datasette-cluster-map]] on Datasette Cloud.
- **datasette-cluster-map 0.18** fixed the breakage and added **[[entities/playwright|Playwright]] tests** run in GitHub Actions.
- **[[entities/datasette-test|datasette-test]] 0.2** provides a `Datasette` test class and a `wait_until_responds()` helper for plugin tests across versions.
- **[[entities/datasette-build|datasette-build]] 0.1a0** is an early skeleton. It aims to load JSON, TSV and CSV files into [[entities/sqlite|SQLite]].
- **[[entities/datasette-edit-templates|datasette-edit-templates]] 0.4.3** lets templates be edited within Datasette and served per instance or per domain.
- The author spent **two days at the annual in-person [[entities/python-software-foundation|Python Software Foundation]] board meeting** working on strategy.
